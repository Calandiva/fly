# Fly — 항공기 증강현실 레이더

휴대폰을 하늘로 들면 **카메라 화면 위에 지금 그 방향을 지나가는 항공기가**
편명·기종·고도·거리와 함께 겹쳐 보입니다. 공개 ADS-B 수신망에서 받은 실제
항공기 위치를, 기기의 GPS·나침반·기울기 센서로 계산한 시선 방향에 맞춰
투영합니다.

의존성 없는 단일 HTML 한 장입니다. 빌드 결과 `index.html` 을 정적 호스팅에
올리면 그대로 동작합니다.

```
python3 build.py          # src/* → index.html, fly.html
npx serve .               # https 또는 localhost 로 열어야 센서가 켜집니다
```

## 어떻게 계산하는가

### 좌표계

월드는 **ENU**(X=동, Y=북, Z=상), 방위는 진북 기준 시계방향을 씁니다.
관측자에서 항공기까지는 대권 거리와 초기 방위각으로 구하고, 고각은 지구
곡률에 의한 침하 `d²/2R` 를 빼서 계산합니다. 35,000 ft 를 순항하는
항공기라도 100 km 밖이면 곡률 보정 없이는 고각이 0.5° 가까이 어긋납니다.

### 짐벌락을 피하는 자세 평활화

`DeviceOrientation` 의 `alpha/beta/gamma` 는 Z-X'-Y'' 내인 회전입니다.
그런데 하늘을 보려고 폰을 세우면 `beta` 가 90° 근처 — **정확히 이 오일러
순서의 짐벌락 지점**이라, 각도를 그대로 저역통과 필터에 넣으면 화면이 심하게
떨립니다. 그래서 매 이벤트를 쿼터니언으로 바꾼 뒤 `slerp` 로 따라가고,
그때서야 회전행렬로 되돌립니다. 보간 계수는 `1 − e^(−k·dt)` 로 잡아
프레임 레이트가 흔들려도 반응 속도가 같게 둡니다.

방위 기준은 기기마다 다릅니다.

* **iOS** — `alpha` 는 임의 기준이라 쓸 수 없고, `webkitCompassHeading`
  (진북 기준 방위)을 받아 `alpha = 360 − heading` 으로 되돌립니다.
* **안드로이드** — `deviceorientationabsolute` 를 씁니다. 이때 상대 기준의
  `deviceorientation` 도 함께 오는데, 두 이벤트의 `alpha` 기준이 달라
  섞어 받으면 방위가 두 값 사이를 오갑니다. 절대 쪽만 받습니다.
* **둘 다 없으면** 방위를 신뢰할 수 없다고 표시하고, 화면 끌기로 직접
  둘러보게 합니다.

### 화면 투영

카메라 영상은 `object-fit: cover` 로 화면을 덮습니다. 광축은 뷰포트
한가운데지만 **수평 화각은 "잘리기 전 영상 전체 폭"에 대응**하므로,
초점거리는 그 폭을 기준으로 잡아야 하늘과 어긋나지 않습니다.

```
scale  = max(화면폭/영상폭, 화면높이/영상높이)
f      = (영상폭 · scale / 2) / tan(화각/2)
화면x  = 중심x + f · (dx / −dz)
화면y  = 중심y − f · (dy / −dz)      // 뒷면 카메라는 기기 −z 를 본다
```

카메라를 끄면 화각을 화면의 **긴 축**에 적용합니다. 세로 화면의 가로에
맞추면 세로 시야가 100° 를 넘어 하늘이 지나치게 퍼져 보입니다.

지평선은 투영 중심을 지나는 평면이라 **화면에서는 언제나 직선**입니다.
월드의 위쪽 벡터를 화면좌표로 옮기면 `nx·u + ny·v = nz` 라는 직선식이 바로
떨어지고, 인공 지평선은 이 반평면으로 화면 사각형을 잘라 칠합니다.
반대로 고각 눈금(0° 가 아닌 원뿔)은 원뿔곡선이라 휘는 게 맞습니다.

### 최근접 통과 예측

현재 속도·기수·상승률이 유지된다고 보고, 관측자와의 시선 거리가 가장
작아지는 시점을 찾습니다. 평면 근사로 풀면 해석해가 나오지만 그 오차가
하필 **정확히 머리 위를 스치는 경우**에 가장 커지므로, 실제 대권 경로 위에서
삼분 탐색으로 찾습니다. 거리는 직선 비행에서 시간에 대해 아래로 볼록하므로
30회면 30분 구간이 0.01초까지 좁혀집니다.

관측이 갱신될 때만 다시 풉니다 — 입력이 그대로면 답도 그대로입니다.
자취를 쌓을 때 관측자 기준 방위·거리·고각을 함께 저장해 두어, 매 프레임
수십 대 × 90점을 다시 계산하지 않습니다. 관측자가 1 km 넘게 움직이면
저장해 둔 값이 더는 맞지 않으므로 자취를 비웁니다.

### 추측항법

공개 피드는 몇 초에 한 번 갱신되지만 화면은 60 fps 로 움직입니다. 마지막
관측을 지상속도·기수·상승률로 현재 시각까지 앞당겨 계산하고, 새 관측이
도착하면 표시 위치를 그쪽으로 **서서히 끌어당깁니다**(`1 − e^(−k·dt)`).
곧바로 갈아끼우면 몇 초마다 항공기가 툭툭 튑니다.

## 데이터 출처

앞에서부터 시도하고, 두 번 연속 실패하면 다음으로 넘어가 그 자리를 기억합니다.

1. [adsb.lol](https://adsb.lol)
2. [adsb.fi](https://adsb.fi)
3. [airplanes.live](https://airplanes.live)
4. [OpenSky Network](https://opensky-network.org)

항로(출발·도착 공항)는 [adsb.lol 의 routeset](https://api.adsb.lol) 에
편명을 모아 한 번에 물어보고 세션 내내 캐시합니다. 본 기능과 완전히 분리해
두어, 이 조회가 죽어도 AR 화면은 그대로 돌아가고 세 번 연속 실패하면 스스로
물러납니다.

모두 무료 공개 API 이고 키가 필요 없습니다. 대신 **커버리지는 지상
수신기가 있는 곳에만** 있습니다. 바다 위나 수신기가 드문 지역은 비어
보일 수 있고, 군용기 등 일부 항공기는 위치를 내보내지 않습니다.
갱신 주기와 조회 반경은 설정에서 조절할 수 있습니다 — 반경을 넓히면
응답이 커지고 공급자 부담도 커집니다.

## 보정

화면 속 항공기가 실제 위치와 어긋난다면 설정에서 두 값을 만집니다.

* **카메라 화각** — 항공기가 실제보다 화면 안쪽/바깥쪽에 몰려 보일 때.
  기본값은 영상 비율에서 추정하지만 기기마다 다릅니다. 멀리 보이는 지형
  지물과 방위 눈금을 맞춰 놓고 조절하면 쉽습니다.
* **방위 보정** — 전체가 좌우로 통째로 밀려 있을 때. 자기 편각이나 주변
  금속·자석 때문에 나침반이 틀어진 경우입니다.

두 값은 브라우저에 저장되어 다음에도 유지됩니다.

## 개인정보

위치와 카메라 영상은 **기기 밖으로 나가지 않습니다.** 영상은 화면에만
그려지고 저장되지 않으며, 서버로는 항공기를 조회할 좌표 범위만 갑니다.
설정은 브라우저 `localStorage` 에만 남습니다.

## 필요 조건

* 카메라와 방향 센서는 **https 또는 localhost** 에서만 켜집니다.
  `file://` 로 열면 데모 모드와 화면 끌기까지만 확인할 수 있습니다.
* iOS 13+ 는 방향 센서에 별도 허용이 필요하며, 그 요청은 반드시 사용자가
  버튼을 누른 그 순간에 떠야 합니다.
* 데스크톱에는 방향 센서가 없습니다. 화면 끌기나 방향키로 둘러보세요.

`node src/_check.js "<검증코드>" [파일...]` 로 브라우저 없이 계산부를
확인할 수 있습니다.

```
node src/_check.js "console.log(Geo.elevation(Geo.nmToM(30), Geo.ftToM(35000)))"
```

카메라 모드는 **실제 하늘을 배경에 깔아 봐야** HUD 가 읽히는지 알 수
있습니다. Chromium 의 기본 가짜 카메라는 초록색 테스트 패턴이라 그
판단이 되지 않습니다.

```
node src/_sky.mjs sky.y4m
chromium --use-fake-device-for-media-stream --use-file-for-fake-video-capture=sky.y4m
```

이 방법으로 밝은 구름 위에서 상태 칩과 고각 눈금이 사라지는 걸 찾았습니다 —
어두운 데모 배경에서는 멀쩡해 보이던 것들입니다. 그래서 HUD 의 선과 글자에는
지도에서 쓰는 방식대로 어두운 테두리를 먼저 깔고 그 위에 그립니다.

## 한계

* 표시 위치는 **수 초 지연된 관측을 앞당겨 계산한 추정치**입니다.
* 최근접 통과 예측은 **직진·정속을 가정**합니다. 선회하거나 속도를 바꾸면
  어긋나고, 접근 중인 항공기일수록 자주 그렇습니다. 근처를 지날지 가늠하는
  용도이지 회피나 안전 판단에 쓸 수 없습니다.
* 항로는 편명으로 추정한 것이라 부정기편·회항·편명 공유에서는 틀릴 수 있습니다.
* ADS-B 를 내보내지 않는 항공기는 보이지 않습니다.
* 나침반 정확도는 주변 자기장에 크게 좌우됩니다.
* **항행·관제·회피 목적으로 쓸 수 없습니다.** 하늘을 구경하기 위한 도구입니다.
